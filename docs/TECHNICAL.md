# 跟川伯聊天：技術說明

給維護與開發的人看的細節。一般介紹請看 [README](../README.md)。

## 體驗流程

1. **開場**：鏡頭從斜 45° 看到立體的品牌拱橋 logo 與 3D 標題，轉正後變成聊天室；川伯自己打招呼（依手機時間說早安/午安/晚安）。
2. **往下滑**：川伯會先出現「…」正在輸入，再跳出訊息；輪到「你」的時候，字會在輸入框裡一個一個打出來，再送出成綠色泡泡。
3. **經歷（約 1/4）**：輝達海外總部落腳北士科一定先講，再隨機一段（三環三線、大巨蛋、土城醫院、小琉球、半工半讀、公館圓環）。
4. **新北的下一段路（約 3/4）**：五大建設全講、順序隨機（AI 科技之都、醫療升級、軌道 123、巨蛋城、都更 5 夠力），再一則長輩最關心的政策＋一則其他政策，中間穿插長輩圖、照片、喝水休息。
5. **結尾**：提醒 11/28 投票、送出專屬「新北事民徽章」（彩紙落下），輸入列變成「分享」。

### 為長輩設計
- 預設約 22px 的 3D 字，「大字」再放大 1.2 倍（介面列不跟著變大，聊天字有更多空間）。
- 「▶ 自動聊」：用長輩閱讀速度自動播放，不用一直滑。
- 「跟川伯說掰掰」：直接快轉到最後。往上翻舊訊息時，右下會出現「↓」回到最新。
- 送出鈕、輸入框也能點：點一下就前進一則（給不習慣滑的人）。
- 第一次進來，對話停住時會跳出「往下滑，繼續聊」。
- 字都可以長按選取、複製（3D 字上方疊了一層對齊的透明真實文字，螢幕閱讀器也讀得到）。
- 點貼圖、照片、長輩圖、徽章、政見卡都能放大、下載、分享。
- 輸入列左邊的齒輪是「設定與說明」：訊息提示音、震動（Android）、立體視角（轉動手機／移動滑鼠）、大字，
  以及「畫面風格」三個滑桿（字的立體厚度、陰影濃淡、手繪感），預設值是最好讀的設定；也列出開源授權與隱私說明。

### 川哥的微縮建設（圖鑑）
小川哥跑步時偶爾會停下來，挖一挖、敲一敲，在旁邊空著的地板上蓋出一個他參與過的建設的微縮模型，點一下就能看大圖、下載、分享。
每種都有等級，第一次蓋出來會標「新！」，收集到的種類記在這支手機（`localStorage` 的 `hl:builds`），卡片上會顯示「圖鑑 n / 11」。

| 等級 | 機率 | 建設（說明都出自 `research/NOTES.md`） |
|---|---|---|
| N | 50% | 學校旁的天橋、抽水站與水門（治水）、新北第一所公托 |
| R | 30% | 台北小巨蛋、台北市政府大樓（信義計畫區監工）、公館圓環改善 |
| SR | 14% | 土城醫院、三環三線 |
| SSR | 5% | 台北大巨蛋、國際 AI 總部大樓（北士科） |
| UR | 1% | 蘆社大橋（下一段路，卡片上寫明是政見） |

- **出現機率**：一支手機時，每次跑步有 18%（`BUILD_RATE`）會蓋一個；多支手機時只有主手機抽出的 3 支「幸運手機」會蓋，而且機率乘上 min(1, 4 / 手機數)（52 支時每支幸運手機約 1.4%），每 5 分鐘重抽一次。
- 只蓋在空地板上：不會蓋住任何一則訊息的字（最多蓋到旁邊的小時間標籤），川哥會先跑到空地旁邊再蓋。SSR、UR 會撒彩紙。
- 模型在 `src/models/scenery.js`（天橋、治水、小巨蛋、市府、公館路口是新做的，其餘沿用寬螢幕的主題模型），邏輯在 `src/fx/builds.js`，卡片在 `src/share/export.js` 的 `buildCard`。

### 多支手機一起玩（實驗功能，預設關閉）
把 2～52 支手機排好平放，迷你川哥會從一支手機的邊緣跑出去、接著從下一支手機的邊緣跑進來，跑到最旁邊再跑回來。手機越多跑越快（兩支 1.5 倍，22 支以上 2.6 倍）。

- **開啟**：設定 → 實驗功能 →「多支手機一起玩」開關打開，再按「開始配對」。只打開開關不會連線。
- **配對**：一支手機按「這支手機顯示配對碼」（這支是「主手機」，管理房間），畫面出現六位數配對碼和 QR 碼；其他手機用相機掃 QR（打開 `/?pair=<碼>`，會先問「要跟其他手機一起玩嗎？」）或在設定裡「我要輸入配對碼」。每支手機加入時拿到一個號碼（主手機是 1 號）。最多 52 支（`MAX_PHONES`），第 53 支會被告知已滿。
- **排好手機**（三種方法）：
  - 2～6 支：由左到右排成一排，用一根手指從最左邊一路滑到最右邊（也可以一個接縫一個接縫滑）。手指從某支手機的邊緣滑出去、過一下下從隔壁手機的對邊滑進來，主手機就把這兩個邊配成一個接縫（時間用 ping 換算成主手機的時鐘），同時記下滑過的高度，川哥跨過去時會保持同樣的高度。只有一種可能時單邊也算。兩支時也可以點「在左邊／在右邊」，三支以上可以依序點「點我排隊」。
  - 7 支以上：照手機上的號碼由左到右、一排一排排好（主手機用「－／＋」調每排幾支），主手機按「排好了，開始！」。
  - 有新手機加入、有手機離開或按「重新排」時，排隊畫面會再出現。
- **資料結構**：接縫存成「B 在 A 的哪一邊（l r u d）」，每支手機再算出格子座標；照號碼排時會產生上下的接縫。川哥沿著每一排左右跑，**每一排一個川哥**。
- **交接**：川哥跑過「外面還有手機」的那條邊時，這支手機把他的狀態（跑步或跌倒的動作與進度、速度、螢幕上的高度、面向、這邊的接縫高度）直接傳給那支，那支從自己的邊把他接著跑進來，並補上網路延遲。同一排只有一支手機「擁有」川哥（主手機記帳，收到 `got` 更新）；點川伯的頭像會把這一排的川哥叫過來。
- **連線方式**：每支手機一條 Supabase Realtime WebSocket，同時加入「房間」（所有手機都聽得到：誰加入、排列、離開；presence 看誰還在）和「自己的信箱」。交接、ping、回報接縫這些只給一支手機的訊息，用 Realtime 的 REST broadcast 直接送進對方信箱，52 支手機時才不會每支都收到全部訊息。不用任何資料表，什麼都不會存進資料庫。
- **斷線**：手機收到背景時會把川哥交給同一排醒著的手機；斷線 25 秒沒回來的手機會被移出房間（之後回來可以再加入）。主手機離開或斷線太久，由號碼最小的手機接手當主手機，房間繼續。少於兩支時就結束。
- **傳了什麼**：臨時的六位數配對碼（當成房間名稱）、每次隨機的代號和號碼、手機排在哪裡（左右上下、滑過的高度）、川哥的位置與動作。不用 GPS、藍牙，不傳個人資料。
- 只在 hammerlee.tw 連 Supabase；本機（localhost）用同一個瀏覽器的 BroadcastChannel 讓多個視窗互通，加 `?realtime` 可以在本機或預覽網址改走 Supabase（真手機測試用）。Artifact 預覽裡不能用。

### 滑太快怎麼辦？
頁面捲動是「目標」，畫面上的進度在追它：已經看過的部分可以自由來回，但往新內容前進時最快每秒約 760px（約 3～4 則），
所以用力一甩只會讓對話「快轉播放」，不會直接跳到結尾。全程約 60～72 則（中位數 66），以閱讀速度約 5～7 分鐘。

## 獨一無二的對話與編號

腳本裡每個可替換的地方都是一個「選擇」（開場白、每則訊息的不同說法、表情、貼圖、圖片或政見卡、主題順序、插曲位置…）。
一段對話就是這一串選擇；把它當成**混合進位數字**讀出來，就是這段對話的編號（約 33 位 16 進位）。
「你」的每句回應都綁在它回應的那段內容上，所以不會出現前後對不起來的回話。

- 總共 **16,573,505,119,485,548,927,319,175,753,786,982,400,000,000（約 1.66 × 10⁴³）** 種不同的對話，遠超過新北 4,037,150 人。
- 編號可以完整解碼回整段對話：分享連結帶著編號（`#c-<編號>`），朋友打開會看到一模一樣的對話。
- 每個主題的公式計數都用暴力列舉驗證過「計數＝實際不同的輸出數」（`node build/test-count.mjs`）。
- **上線後改腳本要小心**：編號是「選擇的順序」，若之後增刪 `script.js` 裡的選項或調整順序，舊的分享編號會解碼成別段對話。
  改腳本時請把 `SCRIPT_VERSION` 加 1、保留舊版腳本檔，並在編號前加上版本（例如 `#c2-<編號>`）讓舊連結用舊腳本重播。
- 徽章上的 `No. XXXX-XXXX-XXXX-XXXX` 是編號的 64 位元雜湊，徽章的外形、金屬、琺瑯配色、圖騰、寶石、緞帶都由它決定。

## 開發

```bash
npm install
tools/fetch_fonts.sh        # 下載粉圓（Huninn）與 Chiron GoRound TC（OFL）
python3 -I tools/photos.py  # 從 research/ 壓縮照片到 public/photos
npm run build               # 會自動掃描 src/ 的所有字、重建 public/glyphs.bin
npm run serve               # http://localhost:5173
```

測試參數：`?nointro` 跳過開場、`?at=30` 直接看到第 30 則、`?debug` 開放 `window.__hl`、`#c-<編號>` 重播某段對話。

多支手機一起玩：`npm run build && npm run serve` 後開幾個窄視窗並排（同一個瀏覽器，走 BroadcastChannel），
都到設定打開開關、一支顯示配對碼、其他輸入；或 `cp tools/pair-twins.html dist/` 後打開 `/pair-twins.html?phones=8&cols=4&w=220&h=440`，一個畫面裡就有 2～12 支「手機」
（一個瀏覽器同時能開的 WebGL 有上限，更多支要用真手機或只跑 `src/net/pair.js` 的模擬）。
`?lag=150` 模擬慢網路；`?realtime` 改走 Supabase Realtime。用兩支真手機測：同一個 Wi‑Fi 下兩支都打開 `http://<電腦 IP>:5173/?realtime`。
建置時若有任何字在兩套字型裡都找不到，會直接失敗，所以不會漏字。

## 在你家擺擺看（AR）

`src/fx/ar.js`。貼圖、徽章、微縮建設的放大視窗，以及長按跑過去的小川哥，都會出現「在你家擺擺看（AR）」：

- **iPhone／iPad（Safari）**：在網頁裡把模型轉成 USDZ（three.js 的 `USDZExporter`），用 `<a rel="ar">` 打開 AR Quick Look。檔案只在手機記憶體裡，不上傳。USDZ 不支援鏡像與一個物件多種材質，所以先把每個零件的位置烘進幾何、一個材質一個零件，再縮成實際大小（貼圖約 22 公分、徽章 16、建設 32、小川哥 28）。Quick Look 的模型是靜止的。
- **Android（Chrome，需要 Google Play 服務的 AR）**：WebXR `immersive-ar`，用 hit-test 找地面或桌面，點一下放上去；小川哥在裡面會繼續動。
- AR 檢視器跑不了我們的卡通著色器和墨線後製，所以模型換成同色系的標準材質，由真實環境打光。
- 其他瀏覽器（例如 LINE 內建瀏覽器）不顯示按鈕；在 LINE 裡會提示改用 Safari／Chrome 打開。
- `vercel.json` 的 Permissions-Policy 允許本站使用 `xr-spatial-tracking` 與相機（WebXR 需要）。

## 投票日與之後

`src/chat/calendar.js` 依台灣時間判斷：11/28 投票日之前是平常的網頁；**投票日當天**依選舉規定不從事競選活動，網頁只顯示「今天是投票日，暫停一天」（`src/ui/daynotice.js`），分享連結也不再邀請、不帶對話；**之後**先顯示感謝頁，按「看看當時的對話」才進入聊天。分享頁的 CDN 快取不會跨過日期分界。
本機可以用 `?day=2026-11-28`、`?day=2026-11-29` 試看看（正式網站上不接受這個參數）。

## 上線

- **網站**：Vercel 專案 `hammerlee-tw`；推上 `main` 就自動部署到 https://hammerlee.tw（`www` 會轉到主網域）。`vercel.json` 設好了安全標頭（不允許被別的網站嵌入、只開放動作感應／分享／剪貼簿等權限）與 `/s/<編號>` 分享頁。
- **分享頁**（`api/share.js`）：從編號本身解出徽章號碼和聊到的政見，產生 LINE / Facebook 的預覽；預覽圖固定是網站自己的 `og-default.png`。每段對話只接受唯一的標準編號，其他寫法一律導回首頁。分享頁不讀資料庫、不用任何上傳的圖片，所以別人沒辦法讓 hammerlee.tw 的連結顯示他自己的圖。
- **資料庫**：Supabase 專案 `hammerlee-tw`（東京）的 `chats` 表只記完成的對話：編號、徽章號碼、聊到的話題、腳本版本、時間。網頁用的公開金鑰（`src/config.js`，本來就是公開的）**只能新增**這幾個欄位，不能讀取、修改、刪除，也不能上傳檔案（`supabase/migrations/`）。團隊要看數字請到 Supabase 後台。只有在 hammerlee.tw 上才會寫入，本機與預覽都不會。
- **Artifact 預覽版**（claude.ai）在沙盒裡，不連外部服務，只把完成的對話記在瀏覽器本機；分享連結用 `#c-<編號>`。

資源「hammerlee.tw｜跟川伯聊天」（juchunko 帳戶，評估 ID `G-0MRNRPCG0C`），只在 hammerlee.tw 上載入。
